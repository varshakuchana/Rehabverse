# Core experience expansion

- HEP review starts with **no included exercises**. `hepReview.ts` owns selection and validation; the saved plan contains only selected, corrected entries and an `originalExtraction` snapshot. Update comparison uses that edited selection. Blank dose fields remain null, and no repetitions are inferred from a hold-only entry.
- `hepQuests.ts` classifies exercises and builds session configuration. A camera match needs an explicit repetition target and no timed hold. Other entries need confirmed repetitions and instructions for Guided mode. Unsupported/insufficient entries remain reference-only. Sets multiply the confirmed per-set count; users follow their plan's rest instructions. Guided holds are self-reported, not camera-verified.
- `movementDetectors.ts` supplies geometry and readiness. Knee geometry and MovementAttemptEngine thresholds are unchanged. Shoulder flexion uses a side-on camera view; shoulder abduction uses a front-facing view. Both measure the selected upper arm relative to the same-side shoulder/hip axis and adapt that measurement to the shared movement engine. Feet, hands and the opposite arm are not required. Camera orientation is instructed, not automatically verified. This is projected movement recognition, not clinical ROM or form assessment. Straight-leg raise is not implemented.
- `TrackedQuest` owns the existing authoritative tracked session. `QuestExperience` selects tracked or Guided presentation. Generated journeys own only an exercise index and advance after an existing session saves. Refresh restarts the journey; saved completed sessions persist independently.
- `exerciseCatalog.ts` is the local query boundary. Generated targets must match its discrete allowlist. `/api/explore` applies deterministic medical-request routing before Gemini, also asks Gemini to reject medical/unsupported requests, and validates every output ID and target. Titles, descriptions and instructor text are application-owned; Gemini cannot supply instructions. The client and stored-quest decoder validate again. Keyword routing is a practical guard, not an exhaustive classifier; test indirect and multilingual requests with the live API too.
- Requests go only to the existing Gemini integration. No camera frames, HEP documents, or progress are sent by Explore. Prompts are not persisted locally. ElevenLabs continues to receive only its existing allowlisted Nova messages.

Run `npm run check:core`, `npm run lint`, and `npx tsc --noEmit`. Core checks mock Gemini and browser storage; no network calls or credentials are used.

Live verification still needed: both shoulder camera views and arms, occlusion/reacquisition, tracking-loss countdown cancellation, SpeechRecognition Start/Begin, Nova audio coordination, template/marked PDF extraction and edits, and Gemini preference matching / medical routing. No browser/camera testing is performed by the deterministic checks.
